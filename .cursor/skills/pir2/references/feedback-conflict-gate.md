# 関連するユーザー指示との整合確認

実装または委任内容を、今回の依頼、適用される指示、判断に影響する既存の feedback と照合する。古い語句の一致、件数、日付だけで矛盾や停止を決めない。Cursor の `Task` を起動する場合は、必要な文脈と実在する report path だけを渡し、通常の `model` は省略または `inherit` とする。

## 確認する内容

- 最新の依頼・仕様が定めるスコープ、除外、受入条件を満たしているか。
- 実装プロンプトが要求された機能、確認、移行を理由なく縮小していないか。
- 参照する feedback が今回の対象に今も適用されるか、後続の明示指示や実測で置き換わっていないか。
- 安全、権限、公開契約、データ保全などの制約を弱めていないか。

feedback や長期記憶は、実際に今回の判断へ影響する経緯がある場合にだけ、利用可能な保存先から該当箇所を読む。固定の日数・件数・ファイル名パターンを必須条件にせず、該当する保存先がないこと自体を障害にしない。

## 矛盾がある場合

実際の correctness、スコープ、権限、安全性に影響する未解決の矛盾が残る場合は、影響を受ける作業を止め、差分・根拠・選択肢を `{RUN_DIR}/feedback-conflict.md` に記録できる形で整理して親エージェントまたはユーザーへ報告する。独立している作業は継続する。

最新の明示指示または十分な実測で矛盾が解消できる場合は、それを採用し、必要なら plan や実装プロンプトの判断根拠を更新する。解消済みの内容について再承認を求めない。

## 記録

後続作業で経緯が必要な場合だけ、既存の plan または `{RUN_DIR}/feedback-conflict.md` に次を残す。

- 参照した feedback と、今回の判断に関係した具体的な記述。
- 矛盾の有無、解消に使った最新指示または実測、影響範囲。
- 未解決なら、停止した作業と必要な判断・権限。

空の照合記録や特定の report の生成を完了条件にしない。
