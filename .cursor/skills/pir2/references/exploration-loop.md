# 能動的再探索と計画の増分更新

メイン Cursor agent は `plan.md` の `### EXPLORATION_NEEDED` と実際の実装リスクを確認し、未解決の具体的な論点が残る場合だけ追加探索を行う。`--deepplan` / `deepplan` が明示された場合は、更新後の再策定を同じ実行ディレクトリで deepplan の手順へ委譲する。スキルの所在は、実行中に解決された Cursor skill directory を起点にし、リポジトリ内の固定パスを前提にしない。

## 収束判定

- 探索が要らない、または論点が実測で解消した場合は次のステップへ進む。
- correctness、security、データ保全、権限、公開契約に関係する未解決の論点がある場合は、根拠を得るまで実装や受入判定を確定しない。
- 低リスクの補足調査は、完了判断を妨げない範囲で backlog として記録できる。topic の数や名称だけで停止しない。

## 追加探索

1. 残っている論点を、必要な証拠が分かる単位に整理する。前回と同じ調査を理由なく繰り返さず、失敗なら入力・環境・権限・推論のどこが原因かを分ける。
2. 独立した論点は別の Cursor `Task`（`subagent_type=explorer`）へ委任し、実行環境の容量と依存関係が許す場合に並列化する。通常の Task は `model` を省略または `inherit` とし、Cursor agent 定義の role に従う。Task 数や探索回数を固定しない。
3. プロンプトには topic、質問、既知の事実、対象範囲、禁止する書き込み・外部操作、参照可能な実在パスを渡す。report が必要な場合だけ親が確定した path を渡し、未生成の report を前提にしない。
4. 探索結果と既存 `plan.md` をメインが読み、新しい事実が影響する要件・スコープ・実装ステップだけを Update で増分修正する。完了済みの判断、ユーザー決定、変更しない範囲を理由なく捨てたり、plan 全体を再作成したりしない。
5. 更新した計画の該当論点を再確認し、解消したら進む。なお不確実なら、原因・残余リスク・次の根拠を報告して bounded な追加探索または必要なユーザー判断を選ぶ。

同じ呼び出しやコマンドが失敗した場合は、既知の原因と修正可能性があるときだけ限定的に再試行する。ツール拒否、安全境界、権限不足を迂回せず、実行していない探索結果や成果物を作らない。
