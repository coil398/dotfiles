# 次ステップキュー管理プロトコル

PIR² 系スキル（/pir2）のステップ 5.6。長時間 run またはユーザーとの対話中断で後続判断を外部に残す必要がある場合だけ、実行予定を checkbox リストで記録する状態管理プロトコル。キューのファイル、項目数、担当数は完了条件ではない。

## 目的

「ユーザーとの対話で中断したあと、次に何をすべきかをスキル本体が失念する」リスクを、必要な run に限って明示状態で抑える。短い run や後続担当・再開の必要がない run では、未生成の queue path を作業条件にしない。

## 5.6-1: 初期内容を Write する（必要時のみ）

sanitized-cwd の手順で作成した実在の `RUN_DIR` があり、長時間 run、対話中断、または後続担当への handoff のために状態保存が必要な場合だけ、`{RUN_DIR}/next-steps.md` を Write する。親が保存先を確定していない場合は作成しない。

キューを作る場合は、実際に予定する項目だけを残し、条件付き項目は該当するときだけ追加する。次のリストは初期内容の例であり、未実行 artifact、固定 reviewer/tester、未選択の gate を要求しない。

```markdown
# 次ステップキュー (run: <実在する RUN_DIR basename>)

最終更新: <ISO8601 現在時刻>

## 残ステップ

- [ ] ステップ 5.7: 破壊的変更チェックリスト（該当時のみ）
- [ ] ステップ 5.8: 直前追加 feedback の自己照合（実際の矛盾がある場合のみ）
- [ ] ステップ 6: 実装（実際に選択した actor / IMPL_INDEX）
- [ ] ステップ 6.5: 実装者の未解決事項ユーザー確認（該当時のみ）
- [ ] ステップ 7: 選択した reviewer 観点のレビュー（該当時のみ）
- [ ] ステップ 7.5: refactor-advisor の提案（ユーザー要望または分離価値がある場合のみ）
- [ ] ステップ 8: tester の確認（動作・安全性の検証が必要な場合のみ）
- [ ] ステップ 9: ウォークスルーの生成（必要または依頼された場合のみ）
- [ ] ステップ 10: メモリへの記録（実際に記録が必要な場合のみ）
- [ ] ステップ 11: retrospector の振り返り（大きな run で分離価値がある場合のみ）
- [ ] ステップ 11.5: handoff.md の完了判定と後処理（handoff が必要な場合のみ）
- [ ] ステップ 12: 最終サマリーの提示
- [ ] ステップ 13: ウォークスルーの提示（必要または依頼された場合のみ）

## 完了済み

（記録対象に選んだ項目が完了するたびに checkbox を `- [x]` に変更し `<!-- done: <ISO8601> -->` を付与する。該当しない条件付き項目は初期内容へ入れない。順序維持のためここに移動しなくてもよい。Read 時に最上位の `- [ ]` を「次に実行すべきステップ」とみなす）
```

ループによる `IMPL_INDEX` / `REVIEW_INDEX` / `TEST_INDEX` の更新は、次ステップキュー更新時に末尾追加する形でよい（最初の 1 件だけ初期版に書き、再ループ時に同じ番号で増えるか別行で追加するかはスキル本体が記録すれば足りる）。

## 5.6-2: 記録対象ステップ完了時の checkbox 更新

キューが存在する場合、記録対象に選んだステップの完了直後に以下を実行する。キューが存在しない run のために、完了報告だけを理由として新しい queue を作らない。

1. 実在する `{RUN_DIR}/next-steps.md` を Read
2. 完了した checkbox を `- [x]` に変更し `<!-- done: <ISO8601> -->` を付与
3. `最終更新` の ISO8601 を現在時刻に更新
4. Write で上書き保存

## 5.6-3: ユーザー会話による中断後の再開

キューが存在する run では、メインエージェント（スキル本体）はユーザーとの対話で中断したあと、次の判断（Task 起動や直接実行など）の前に `{RUN_DIR}/next-steps.md` を Read する。未チェックの最上位 checkbox が「次に実行すべきステップ」を示す。キューがなければ、現在の差分・依頼・実在する plan から再開判断を行い、未生成 path を補わない。

判断記録はキューがある場合だけ `{RUN_DIR}/next-steps.md` の末尾セクション（`## 中断・再開ログ`、初期版にはなくてよい。発生時に追記）に以下の形式で残す:

```
- <ISO8601>: ユーザー会話で中断（理由: <要約>）→ 再開時に Read。次ステップ: <最上位 [ ] のステップ>
```

## スキップ条件

- 短い run、対話中断がない run、後続担当への handoff が不要な run は queue を生成しない。
- reviewer、refactor-advisor、tester、walkthrough、memory、retrospector はリスク、依頼、実行価値に応じて選び、選ばない項目を未実行 gate として残さない。
- `RESUME_MODE=resume` の場合だけ、親が安全性を確認した実在の `handoff.md` の未完了項目を残ステップへ統合する。handoff がない、または読めない場合に架空の項目・path・report を生成しない。
