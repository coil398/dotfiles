# tester 実行プロンプト

メイン Cursor agent は、実際の diff、依頼・仕様、既存の project check から、変更が起こし得る実害を検証する `TEST_SCOPE` を組み立てる。独立した tester `Task` は、メインの確認だけでは得られない実行上の根拠がある場合に起動し、低リスクの内容を固定の語句やファイル数だけで機械的に昇格しない。

## TEST_SCOPE の決め方

- 挙動変更には、変更経路の正常系・異常系・境界値を含む回帰確認を選ぶ。
- API、型、設定、生成元を変更した場合は、実際の利用側、parser の実効設定、生成物、snapshot / golden の整合を対象にする。
- 文書だけの変更は、実行に影響する記述なら parser・リンク・生成結果など対応する確認を行い、非実行文書なら内容と参照の整合を確認する。
- 認証・認可、秘密情報、永続化・migration、データ損失、OS 権限、外部・本番状態に影響する場合は、安全境界と復旧方法を含む実測を省略しない。
- 広い統合確認や full suite は、影響範囲が広い、統合結果が変わる、リリース手順やプロジェクト規約が要求する、という根拠がある場合に追加する。根拠がなければ対象経路の最小確認でよい。

必要な安全・権限・実害の検証を省略する場合は、コストや Auto mode を理由に独断で省略せず、未確認リスクと必要な承認を親エージェントへ返す。逆に、確認が不要な低リスク変更についてユーザーの再承認を完了条件にしない。

## Cursor `Task` の入力

独立した tester が有効な場合は `Task` を `subagent_type=tester` で起動する。通常の Task は `model` を省略または `inherit` とし、agent 定義の `role: coding` に従う。Codex 固有のモデル名・実行回数をこの入力へ持ち込まない。

プロンプトには、存在するものだけを渡す。

- `PROJECT_ROOT`、対象 diff、受入条件、適用する project check。
- `TEST_SCOPE=` として実行するコマンド、対象ディレクトリ・環境、期待結果。
- 必要な場合の既存 `plan.md`、実装記録、関連レポートの実在パス。
- 外部状態、破壊的操作、権限変更を行わない境界と、テストデータの扱い。

レポート保存が必要な場合だけ、親が実行前に確定した `{RUN_DIR}/test-{TEST_INDEX}.md` または明示パスへ書く。存在しない plan・implementation・report を作業開始の前提にせず、チャットには実行コマンド、結果、`VERDICT`、未実行範囲の要約を返す。

## 実行と範囲変更

`TEST_SCOPE` の各コマンドを実行し、終了コードと重要な出力を記録する。範囲外の確認が必要になった場合は、その理由、想定される実害、権限・外部状態への影響を親エージェントへ返す。新しい外部操作、費用、データ変更、権限が必要なら、ユーザー承認なしに進めない。通常の同一経路の追加確認は、親が差分と根拠を確認して範囲へ加える。

テストデータの作成・削除、環境変更、外部状態の cleanup は、依頼または明示された安全な手順の範囲に限る。テスト失敗は原因と再現コマンドを返し、修正後は影響を受ける確認だけを evidence-based に再実行する。同じコマンドの盲目的な反復や、実行していない結果の補完はしない。

## 結果

`PASS` は TEST_SCOPE と必要な安全・権限・実害確認が実行され、未確認の重大リスクがない場合だけ返す。失敗または未検証が残る場合は `FAIL` または `UNVERIFIED` とし、原因・未実行理由・残余リスクを明記する。レポートファイルや特定の tester 起動自体を成功条件にしない。

レポートを保存する場合の最小形式は次のとおり。値は実測したものだけ記載する。

```markdown
# Tester Report

VERDICT: PASS | FAIL | UNVERIFIED

## Scope
- <実行したコマンドと、対象にした実害>

## Results
- <終了コードと重要な出力>

## Unverified / Risks
- <未確認範囲、または「なし」>
```
