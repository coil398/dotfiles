# 変更の影響と検証範囲

PIR² スキル（/pir2）のステップ 5.7。メイン Cursor agent が plan、explorer report、対象 diff から公開契約への波及と実行時の挙動変更を分けて確認し、必要な review / test の範囲を決める。キーワード、ファイル数、フラグ名だけでは工程を発火させない。

このファイルは Cursor の pir2 用です。Task の起動、report、model は Cursor native skill の契約に従います。

## 影響の確認

対象 diff と依頼・仕様から、次の実害につながる影響を確認します。

- 公開 API・型・設定の名前、必須性、入力・出力の意味、互換性。
- データの永続化、migration、認証・認可、秘密情報、外部・本番操作。
- 生成元から生成物への連鎖と、実際に影響する snapshot / golden / 利用側。
- 分岐、状態、順序、非同期処理、エラー処理などの実行時挙動。
- プロジェクト固有のリリース条件、既存の必須検証、復旧方法。

controller の件数、特定語の出現、生成処理への言及だけで破壊的変更とは判定しません。変更が表面的でも公開契約や安全境界を変えるなら、その実態を根拠に高い確認を選びます。

## 検証の選定

影響ごとに、差分確認、reviewer、tester、プロジェクト規約のどれで実害を検証するかを plan の検証欄へ記録します。

- 挙動を変えない文書・設定変更は、内容整合、対応 parser、実効設定、生成結果など変更に即した確認を行います。
- 挙動変更は対象経路の回帰テストを実行し、必要なら正常系・異常系・境界値を追加・更新します。
- API・型・生成物の変更は生成元、利用側、snapshot / golden の整合を確認します。
- データ損失、認証・認可、秘密情報、OS権限、外部・本番状態に影響する場合は、独立した security / architecture review と実動作確認、復旧方法の確認を選びます。
- 影響範囲が広い、統合で結果が変わる、またはプロジェクトの必須手順がある場合だけ、該当する統合テストや full suite を追加します。

reviewer の人数、全観点、refactor-advisor、テストの反復回数自体は品質条件にしません。必要な検証ができない場合は未検証のリスクを明記し、成功として扱いません。

## 権限

本番・削除・不可逆な外部操作、OS/security/権限境界の変更は、対象、影響、復旧方法を示してユーザーの明示承認を得ます。検証コストを理由に既存の安全境界を緩めません。

## 記録（必要な場合）

独立した記録が後続判断に役立つ場合だけ `{RUN_DIR}/destructive-change-check.md` に次を残します。

- 対象 diff と依頼・仕様から確認した影響、その根拠。
- 選択した reviewer / tester / project check と、防ぐ実害。
- 未確認の範囲、必要な権限、復旧方法。
- broad check や full suite を実行しなかった場合の理由。

記録ファイルの存在、特定のフラグ、固定された工程数を完了条件にしません。メイン Cursor agent は実際の差分、コマンド結果、reviewer / tester の報告から受入を判定します。
