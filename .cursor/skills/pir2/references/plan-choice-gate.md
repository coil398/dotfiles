# 計画でユーザー判断が必要な場合

PIR² 系スキル（/pir2）のステップ 4.6。メイン Cursor agent が依頼、既存実装、適用指示、実測結果から通常の実装詳細を決められず、成果物や権限に実質的な影響がある場合だけユーザー判断を求める。見出し、キーワード、複数案の存在だけでは発動しない。

## 確認が必要な判断

- 要求された結果を縮小したり、実データをモック・代替経路へ置き換えたりするため、ユーザーの目的が変わる。
- 未承認の外部操作、追加権限、費用、データ損失、または本番状態への影響を伴う。
- 調査しても、正しさや公開仕様に影響する複数の解釈が残り、安全に一つを選べない。
- ユーザーが明示的に選択権を留保している。

上記に該当する範囲だけを待機させ、独立して完了できる作業は進める。既存の依頼・仕様・多数派の実装から安全に決められる詳細は、根拠を plan に記録して継続する。

## 確認フォーマット

メイン Cursor agent は `{RUN_DIR}/plan.md` の該当箇所を Read し、判断が必要な根拠、確認済みの事実、各選択肢の影響・リスク、推奨案を以下の形式で提示します。独立して進められる作業は止めず、再承認が不要な明示指示を繰り返し尋ねません。

```
## プラン段階のユーザー判断要請

[メインが plan.md に記載した複数案 / 縮小判断 / 外部依存ギャップの要約 — 1〜3 文]

判断要請の理由: [plan.md に記載した「なぜユーザー判断が必要か」をそのまま転記]

選択肢:
- (A) [案 A] — [メインが記載した内容と理由・トレードオフ]
- (B) [案 B] — ...
- (C) ...
- 別案: [自由記述で別アプローチを指示]

メインの推奨案: [plan.md で「推奨案」として挙げた選択肢と理由を転記。最終判断はユーザー]

どれで進めますか？
```

## 運用ルール

- 実質的な判断が必要な場合は、plan の根拠、影響・リスク、推奨案を示してユーザーに尋ねる。明示された依頼を再承認させない。
- ゲート名、疑問形、選択肢の語だけでは停止しない。ユーザーの意図が明確で安全な最小解釈に定まる場合は、その解釈と理由を記録して進める。
- 自由記述の代替案が既存の計画をどう変えるか一意に決められない場合だけ、変更範囲、維持する範囲、影響する完了条件を短く確認する。単一の解釈に定まる場合は追加ゲートを作らない。
- ユーザーの回答は `{RUN_DIR}/user-decisions.md` に記録し、影響する plan の要件・scope・依存だけを Edit で増分更新する。完了済みの判断・ステップ・決定を保持し、計画全体を破棄・再作成しない。
- 権限・安全境界・不可逆な外部操作に関する確認を、Auto mode、実装可能性、時間や検証コストを理由に省略しない。独立して完了できる作業は待機中も進める。
