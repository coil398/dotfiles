# Writing-plan — Cursor

このnative入口の実体ディレクトリを基準に、共有原本 [../../../.agents/skills/writing-plan/SKILL.md](../../../.agents/skills/writing-plan/SKILL.md) を最初にReadします。別配置で起動されて相対pathを解決できない場合は、親が実在確認して渡した共有Skillの絶対pathを使います。親Cursor agentが要件、対象版、計画、依存、所有、統合、受入、記録を所有します。

## 計画

- 親が依頼、status/diff、既存計画、関連コード、成功条件を確認します。結果を変える未決定だけをユーザーへ確認し、完了項目を再計画しません。
- `--deepplan` が明示された場合だけ共通deepplanを読み、親が結果を対象コードと照合します。
- 独立した計画案の比較が必要な場合だけ Cursor の標準 Task を使います。Taskには共有 `writing-plan/references/planner.md` の実体path、対象版、確定事実、所有、編集禁止、チャット返却を渡し、planner担当自身にreferenceをReadさせます。`planner` は作業のラベルであり、標準Taskで表せない実行条件がない限り固定識別子として要求しません。保存せず、親の計画・受入・ユーザー判断を置き換えません。
- Taskの起動値は親のruntime方針に従い、固定数・固定ラウンド・空のartifactを要求しません。

計画には目標・非目標、根拠、対象ファイルと排他的所有、依存順、各ステップの完了条件、focused check、リスク、未解決判断を含めます。既存計画は決定事項と完了項目を保って増分更新します。計画だけの依頼では実装を開始しません。

## 記録・実装・確認

後段が参照する、またはユーザーが求めた場合だけ、親が実在を確認した親directory配下の今回未使用のファイルpath（通常は `docs/plans/...`）へ保存します。計画案を比較するTaskには保存、記憶追記、コード変更をさせません。実装を委任するTaskは、親が確定した目的、所有範囲、編集権限、完了条件を渡したwriterとして扱い、その範囲だけ変更できます。小さく密結合した変更は親が直接実装します。子へ親用 `/writing-plan` の計画・実装・記録ループを渡して同じ工程を再起動させません。

親はstatus、対象diff、実在ファイル、要求、実行結果を照合します。レビュー・テストは変更の実害に応じて選び、固定の全観点・人数・ラウンドを既定にしません。失敗・timeout・未確認をPASSへ変換せず、影響した範囲だけ原因を特定して再確認します。

ユーザーの未コミット変更を戻さず、明示範囲外のreset、restore、checkout、stash、commit、push、外部投稿をしません。完了時は実装記録の実在path、変更、レビュー、テスト、未確認事項を返します。
