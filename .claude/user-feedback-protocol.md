# ユーザー指摘からの改善

具体的な不具合、見逃し、期待との差を指摘され、その学びが今後の判断を変えるときに使う。単発の好みや今回だけの修正を、常設ルールへ自動昇格させない。

## 手順

1. 依頼された修正と必要な検証を先に完了する。
2. 原因が再発しうる場合、コード、手順、評価観点、知識のどこが不足していたかを特定する。ユーザーが原因分析を求めた場合は必ず結果を示す。
3. 次の条件をすべて満たすときだけ、再利用できる最小のルールとして正しいSSOTへ反映する。
   - 同種の作業で再発しうる。
   - 安定した観点・知識・制約として表現できる。
   - 既存ルールと重複せず、読者が必要な場面で到達できる。
4. 修正、SSOT更新、検証結果を報告する。依頼範囲外の変更が必要なら、独立した準備を済ませてから対象と影響を確認する。

## 反映先

| 内容 | 反映先 |
|---|---|
| reviewer等の評価観点不足 | 該当agentまたはreview基準 |
| 実装に必要なdomain知識 | 該当する設計SSOT・checklist・skill reference |
| runtime横断またはClaude固有の運用 | 適用範囲に合う `AGENTS.md` / `CLAUDE.md` / skill |
| 特定projectだけの規約 | そのprojectの `CLAUDE.md` または関連SSOT |
| 後から検索する価値がある経緯・判断 | LTM。既存SSOTの本文は重複保存しない |
| 短期の試行方針 | field-notes |

memoryは実行時に必ず読まれるSSOTではない。観点・知識・ルールをmemoryだけへ置かず、既にSSOTへ反映した内容を二重保存しない。

## 見送るもの

- 再発条件を説明できない単発ケース。
- 既存ルールで既に扱える内容。
- 行動を変えない経緯、感情的な言い換え、特定チケットの固有名。
- 現時点の失敗だけを通すskip、hook、固定値、追加承認gate。

retrospectorは複数runの観測からパターンを汎化する。本プロトコルは現在の依頼を処理するメインClaudeが使い、retrospectorのlog集計と二重に同じ規則を追加しない。
