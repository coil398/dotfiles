# コードベース探索の委譲

複数ファイルの探索を独立したbounded unitへ分ける価値があるときに使う。メインClaudeは対象、依存関係、受入、結果統合を所有する。

## 直接確認する場面

- パスが既知の単一ファイル、ユーザーが提示したファイル、`git status` / `git diff`など軽量な状態確認。
- 小さく密結合で、分離すると同じcontextを重複して渡すだけになる調査。
- メインの次の判断に即座に必要で、同時に進められる別作業がない確認。

## explorerへ委譲する場面

- 独立した領域を並列に調べられる。
- パターン列挙、影響範囲、同一レイヤーの実装比較など、まとまった探索結果を後段で再利用する。
- 読取専用の探索をwriterから分離すると、所有範囲と証拠が明確になる。

Agent数は調査領域と利用可能なcapacityから決める。小さなタスクを人数のために分割せず、重複する領域は1 unitへまとめる。ユーザーが独立評価、panel、特定モデルを指定した場合はその方式を保持する。

## 起動契約

各explorerへ次を渡す。

- 調査目的と対象path・version
- 確定事実、仮説、未確認事項
- read-onlyの所有範囲と変更禁止
- 必要な出力。通常は対象ファイル・行、観測事実、未確認、後段への示唆
- 必要な専門資料の実体path

ユーザーが限定した対象はそのまま渡す。字義範囲を超える網羅調査へ広げない。外部仕様が関わるときは公式一次情報とURLを求める。

複数レポートはラベル番号ではなく対象ファイル・論点で統合し、重複と矛盾を照合する。追加探索は、残った不明点が受入や設計を変える場合だけ行う。

## nested Agent

Claude Code v2.1.172以降では、`Agent` toolを持つsubagentがnested Agentを起動できる。PIR²の制御フローはメインClaudeに残し、planner / implementer / reviewerからのnested起動はread-onlyのexplorerに限定する。explorer自身はさらにnested起動しない。`Agent` toolを持たないsubagentは、必要な追加探索を返却結果でメインへ依頼する。

Agent Teamsを明示された作業では、`TeamCreate`、共有context、messagingを使う。単なるsubagentの逐次起動をteamと呼ばない。
