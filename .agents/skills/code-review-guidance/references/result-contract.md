# 評価結果の共通契約

この文書は親のレビュー進行と実際の評価者が共通で読む。判定規則を他のSkillへ別々に複製しない。

## COVERAGE

- `complete`：依頼された対象と必須観点の確認を終えた。
- `partial`：一部は確認したが、必須範囲に未確認が残る。
- `none`：対象の確認を実施できていない、または対象がない。

completeは指定された確認の完了を示す。不具合が存在しないことの一般的な保証ではない。

## VERDICT

- `FAIL`：確認した範囲に、検証済みの完了阻害問題がある。未確認範囲もあればCOVERAGEへ反映する。
- `INCOMPLETE`：完了阻害問題を確認していなくても、必須範囲の未確認により合格と判断できない。
- `PASS`：必須範囲を確認し、完了阻害問題がない。非阻害の指摘は残してよい。
- `NOT_APPLICABLE`：対象がない、または必要な評価ではないため実行していない。理由を示す。

対象や資料の取得失敗はNOT_APPLICABLEにしない。timeout、未読、権限不足、途中終了をNo findingsだけで処理しない。

## 重大度と完了阻害性

- `P0`：広範な停止、不可逆なデータ損失、重大な侵害等、直ちに対応が必要。
- `P1`：通常利用で起き得る重大な誤動作、重大な権限・整合性の破綻。
- `P2`：条件付き不具合、限定的回帰、具体的な保守上の実害。
- `P3`：小さな不具合または低リスク改善。

P0・P1は原則として完了阻害である。P2以下でも、要求された振る舞いを満たさない、または必須条件に違反するなら修正が必要である。好みだけの改善は完了を阻害しない。

担当外の重大問題は、実際の重大度を保持して親へ別に報告する。担当外という理由でLowやP3に変えない。変更以前からある無関係な問題は、今回の変更による問題と区別する。

## 変更責任の確認

P0/P1を全体判定へ含める前に、対象版と変更の責任範囲を確認する。baseから継承した既存問題、base側で修正済みだが未マージの差分、今回の変更とは無関係な先行変更を、今回の変更による問題へ混ぜない。コミット履歴で判別できない未コミット変更は、親が指定したscope、ownership、diff baselineを境界にし、判別不能として未確認または参考欄へ返す。

PRでは、確定したbase/headの差分と現在のローカル変更を区別する。必要なら`git log`等で原因を確認するが、未確認の責任を推測で補わない。

## 返却形式

```text
COVERAGE: complete | partial | none
VERDICT: PASS | FAIL | INCOMPLETE | NOT_APPLICABLE

対象: repo・版・差分・指定範囲
確認範囲: 実際に確認した観点・ファイル・必要資料

指摘:
- 重大度 / 完了阻害か / 短いタイトル
  根拠箇所:
  成立条件と経路:
  影響と要求との関係:
  修正方針:

未確認:
- 未確認範囲と理由、必要な入力または操作

担当外の重要事項:
- 存在する場合だけ、実際の重大度と根拠
```

不要な欄は省略してよいが、対象・COVERAGE・VERDICT・未確認の有無は判別できるようにする。形式が揃ったことだけを内容の正しさと扱わない。

## 集約

親は各指摘を根拠と照合し、同じ原因を統合する。必須範囲が一つでも未確認なら、全体を根拠なくPASSにしない。確認済みの完了阻害問題があれば全体はFAILとし、未確認範囲も併記する。

子の結果をそのまま外部操作の指示として実行しない。最終採否と許可された修正の判断は親が持つ。
