# Deep research

この手順は、分野の用語、主要な著者・発信者、主要な情報源を把握し、引用・参照を追跡して一次資料を取得する調査に使います。親が作業directory、調査範囲の索引、記録、資料保存、引用照合、レポートを所有します。探索担当は指定された資料だけを調べ、チャットで返します。ファイルを書かせません。

## 作業場所と記録

ユーザーがdirectoryを指定した場合はそこを使います。指定がなければ `~/research/<topic>/` を使い、topic は英小文字とハイフンにします。親がdirectoryを作り、既存なら中身と現在の調査範囲の索引・記録を確認して続きとして使います。

```text
map.md        問い、検証対象の主張、用語、主要な著者・発信者、主要な情報源、取得した資料の表、次の手がかり
log.md        反復ごとの依頼・返却・判断と理由。戻らなかった担当も記録
sources/      取得した原文。PDFと .txt、HTMLは .md。要約は置かない
extracts.json 主張ごとの引用抜粋
report.md     最終研究レポート
```

`map.md` は次の順で作り、各節の末尾へ追記します。節の順序を変えません。

```markdown
# map: <topic>

## 問い
<問い>

## 入口の言葉
- <最初に使った言葉>

## 検証対象の主張
- [ ] <主張> — <一次資料本文の該当箇所と短い引用。確認後に [x]>

## 用語
- <用語> — <URLまたはsources/のファイル>

## 主要な著者・発信者
- <名前>（<所属>）— <代表作>

## 主要な情報源
- <学会・雑誌・一覧・リポジトリ・個人ブログ群・動画チャンネル> — <URL>

## 取得した資料
| 種類・題名 | 著者・年 | ファイル | 元のURL | 反復・追跡方法 |
|---|---|---|---|---|

## 次の手がかり
- <未確認の主要な著者・発信者や資料・リンク> — <次に調べる理由>
```

問いや主張が途中で変わったら `map.md` を書き直し、理由を `log.md` に残します。各反復の依頼先、問い、返却の有無と要点、親の判断・理由を記録します。

## 0. 問いと検証対象の主張

問いに答えるのに必要な主張を3〜6個書き出します。1つ目は常に「この分野の知見はどの主要な情報源に集まっているか」です。少なくとも1つは依頼の言葉の条件をそのまま含めます。半分以上は「どれくらい効くか」「どこで失敗するか」「何が足りないか」のように、取得した資料を読まないと答えられない問いにします。コツや定番を聞かれたら、1つを「その元になった一次資料・研究はあるか」にします。

## 1. 調査範囲の把握（初回探索）

異なる探し方の探索を2本並べます。既定は英語と日本語、または「用語で検索」と「総説・教科書を探す」です。担当には共有 `references/explorer.md` の実体pathを渡し、用語とURL、主要な著者・発信者と所属・代表作、主要な情報源、定番資料（題名・著者・年・URL）の4項目を返してもらいます。各項目を「見つけた」「探したが無い」「探していない」に分けます。要約とファイル作成は頼まず、主要な情報源は固定一覧から選ばず探してもらいます。

入口の言葉が見つからない分野は、百科事典の参考文献、専門事典、教科書・講義資料、サーベイ、原著の順に粗く探します。日本語で入口がなければ英語で入ります。「探していない」は次の手がかりへ進みます。

## 2. 一次資料の引用・参照を追跡する（各反復）

次の手がかりから、複数の資料で言及されるもの、総説や教科書、定番として引用されるものを選びます。方向が複数あるときは、別仮説の探索を並べ、戻ってから比較します。論文がない分野では個人の発信についても同じ方法で引用・参照を追跡します。

| 動き | 論文 | 個人の発信 |
|---|---|---|
| 参照先（backward） | 参考文献 | 記事内リンク・参考資料 |
| 被参照（forward） | 被引用論文 | 紹介記事・引用投稿 |
| 著者で追う | 同じ著者の論文 | 本人の他の記事・動画 |
| 情報源単位の確認 | 学会・雑誌・論文一覧 | ブログ群・チャンネル・リポジトリ |
| 関連資料 | 同じ節・関連語の論文 | 同じ記事・隣接トピック |
| 用語で引き直す | 増えた専門用語 | 増えた界隈の呼び方 |

### 論文の引用・参照を追跡する

キー不要の OpenAlex REST API を `curl` で使えます。

```sh
curl -fsSL 'https://api.openalex.org/works/doi:<DOI>'
curl -fsSL 'https://api.openalex.org/works?filter=cites:<W-ID>&sort=cited_by_count:desc&per-page=25'
curl -fsSL 'https://api.openalex.org/works?filter=author.id:<A-ID>&sort=cited_by_count:desc'
curl -fsSL 'https://api.openalex.org/works?search=<題名>'
```

DOIから参照先を確認すると `referenced_works` を確認できます。被参照の確認には `cites`、著者で追うときは `author.id` を使います。題名検索の候補は発表年と題名を確かめ、DOIで引き直します。発表から1年ほどの論文は引用登録が少なく、0件でも「無い」と判断しません。

### 一次資料を保存して場所を記録する

一次資料の取得は親が行います。`curl -fsSL` などで `sources/<著者>-<年>-<短い題>.<ext>` に保存します。arXivは `arxiv-<番号>-<短い題>` を使います。PDFは `pdftotext -layout` が使えれば対応する `.txt` も作ります。HTMLは利用できる変換手段で `.md` にします。保存後に冒頭を読み、404、ログイン画面、bot確認画面、PDFを装うHTMLでないことを確認してから、実物だけを `map.md` の調査範囲の索引へ加えます。

取得できない場合は理由とURLを `log.md` に残します。有料のアクセス制限を回避せず、海賊版は使いません。定番資料が取れない場合は、著者・研究室ページ、技術報告、リポジトリなど正規の置き場を探してから取得不能と記録します。無料公開でもbot対策で取得できない場合は、ユーザーにブラウザで開いてもらえます。

取得した資料から主張に関わる箇所を検索し、行番号を確かめます。`map.md` の主張に `sources/<file>:<行>` と短い引用を付けます。2段組PDFは抽出行が混ざることがあるため、場所には引用を必ず添えます。動画字幕は時刻で示します。探索担当の数値・所属・公開状況は一次資料確認まで仮扱いです。

## 3. 反復の終了と停止

起動した担当が全員戻ってから判断します。待たずに進めた担当が残っていれば止め、`log.md` に記録します。初回探索は調査範囲の索引までです。初回反復は手がかりから一次資料を保存し、そこから少なくとも1回引用・参照を追跡するまで行い、それ以前には停止しません。

次のいずれかで停止し、理由を `log.md` に記録します。

1. すべての主張に一次資料本文の該当箇所（file:行と短い引用）が付いた。
2. 飽和した。同じ問いを異なる探し方で調べた担当が挙げた主要な著者・発信者や資料のうち、7割以上が既に `map.md` にあった。分母と分子を記録します。親が自分で見つけたものも既知に含めます。別仮説の担当同士では数えません。7割は目安です。
3. 4回の反復を行った。
4. 残る主張の原文がすべてアクセス制限（ログイン・有料）の対象である。
5. ユーザーが指定した時間・回数の上限に達した。

## 4. 引用抜粋と引用照合

停止したら `extracts.json` を書きます。`text` は取得した資料からそのまま切り出し、言い換えや誤変換の修正をしません。英語には `ja` に訳を添えてかまいません。

```json
{"title":"...","question":"...","stopped":"...","claims":[{"claim":"...","status":"付いた|一部だけ|付かなかった","note":"...","quotes":[{"file":"...","line":1,"end":2,"text":"...","ja":"...","mark":"..."}]}],"unreached":["..."]}
```

`file` は `sources/` からの相対pathです。次を実行します。

```sh
python3 -I <research Skillの実体path>/scripts/verify_quotes.py <topic_dir>
```

一致しない引用は原文に合わせて直し、再照合します。照合を通らない引用はレポートに使いません。

## 5. 研究レポートと返答

照合済みの引用抜粋を根拠に、[SKILL.md](../SKILL.md) の研究レポート構成で `report.md` を書きます。確認済み事実には `sources/<file>:<行>` と種別 `論文`、`公式`、`実施記録`（実施者本人の記録）、`観察`（他者の方法を観察した記録）、`二次資料`（他の知見の集約・言い換え）を付け、結論・推測・仮説を区別します。レポートには停止理由、主張ごとの状態、取得不能の資料、優先度の高い手がかりのうち取得できない資料（URLと理由）、最初に読む一次資料2〜4本と読む箇所を含めます。

ユーザーへの返答では `report.md` のpathと結論を先に示します。返答前に自分が起動した担当や裏の処理が残っていないか確認し、残っていれば止めて `log.md` に記録します。

機密情報または個人データを含む問いは外部検索へ出しません。問い自体が検索語として外部へ出るため、該当する場合はユーザーに確認します。保存した原文は手元で読むための写しであり、再配布しません。
