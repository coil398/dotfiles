# Research — 調査・思考・仮説

**テーマ**: `$ARGUMENTS`

親が問い、範囲、調査対象、統合、受入、最終判断を所有します。調査担当は資料を読み、根拠と不確実性をチャットで返します。担当へファイル編集、テスト生成、記憶追記、外部投稿を要求しません。

## 1. 問いと調査範囲

親は問いを、確認したい事実、比較、因果、反証、仮説などに分解します。ユーザーが既に与えた対象や条件を再質問せず、研究結果を実質的に変える未決定だけを確認します。

Web資料とローカル資料は、問いの根拠に必要な場合だけ使います。最新仕様、リリース、法令、価格など時点で変わる情報は一次資料で確認します。ローカル実装の意味を調べる問いでは、実在する対象版と関連ファイルを確認します。両方を機械的に要求せず、使わなかった理由を必要なら記録します。

## 2. 調査の委譲

独立したサブ問いがあり分離の利益がある場合だけ、現在のランタイムの read-only primitive で調査担当を起動します。担当数・最低数・上限・モデル・起動順を固定しません。小さな問いや資料が揃っている問いは親が直接調べられます。

担当への入力には、研究テーマ、担当サブ問い、対象と版、確認済み事実、変更禁止範囲、必要な出典、返却形式を含めます。担当は実際に確認できた資料だけを報告し、取得不能・未読・timeoutを「反証なし」や成功へ変換しません。

ライブラリ選定や技術比較が主目的なら、汎用探索担当に選定責任を持たせず、現在のランタイムで利用可能な技術検証担当または親が一次資料を比較します。実在する共有実行者用手順が必要な場合は `references/` の専門資料を親が担当へ明示します。

## 3. 集約と分析

親は調査結果を読み、重複をまとめ、出典付き事実、弱い情報、推測、対立、空白を分けます。研究結果を変える不明点だけ追加調査へ戻し、回数を完了条件にしません。

思考担当へ渡す場合は、実在する集約結果、テーマ、rubric、対象版を入力し、新規調査を禁止します。思考担当は論点、パターン、因果と相関、前提、反例、追加調査の必要性を返します。仮説担当へ渡す場合は、思考結果と根拠を入力し、検証可能性・反証条件・確信度を求めます。担当の専門手順は次の reference を読みます。

- `references/explorer.md`: 資料・コードの探索と根拠の返却
- `references/tech-validator.md`: 技術選定・比較の一次資料確認
- `references/thinker.md`: 集約結果の構造分析
- `references/hypothesizer.md`: 反証可能な仮説の作成

これらの担当は結果を保存しません。後段が全文を参照する実益がある場合だけ、親が安全性と未使用性を確認した path に保存します。

## 4. 研究レポート

親は必要な場合だけ、調査・思考・仮説を一つの自己完結した研究レポートへ統合します。中間ファイルを読まない読者でも判断できるよう、確認事実の出典、推測のラベル、仮説ごとの根拠・検証方法・反証条件・確信度、未解決の問いを落としません。

最低限の構成:

```markdown
# [テーマ] 研究レポート
## 0. 結論と最重要の判断
## 1. 問い・範囲・前提
## 2. 確認済み事実（出典付き）
## 3. 不確実性・対立・反証
## 4. 仮説（根拠 / 検証方法 / 反証条件 / 確信度）
## 5. 推奨する次の確認
## 6. 未解決の問いと参照資料
```

保存する場合は、親または呼び出し元が指定した親directoryの実在を確認し、その配下の今回未使用のファイルpathだけを使い、保存後にファイルpathの実在を確認します。保存しない場合は確認できた内容をチャットで返します。未指定のRUN_DIR、固定メモリ、handoff、台帳は作りません。

## 5. 完了と未完了

研究の完了条件は、依頼された問いに対する根拠付きの結果、残る不確実性、必要な次の確認が返っていることです。担当の途中終了、資料取得失敗、モデル不在、権限不足は `INCOMPLETE` として範囲と原因を示します。推測で補ったり、別方式へ黙って切り替えたりしません。研究結果を実装、commit、push、外部投稿へ拡張する場合は別の明示依頼として扱います。
