# Research — 調査 → 思考 → 仮説

研究テーマを、調査、集約、分析、仮説形成の順に整理します。親が要件、スコープ、統合、受入、最終判断を保持し、必要な独立作業だけを現在のランタイムが提供する委譲 primitive に渡します。委譲できない場合は親が直接行い、実行方式、人数、モデル、ネスト、レポート形式を完了条件にしません。

**テーマ**: $ARGUMENTS

各フェーズの担当と実行方式:

| フェーズ | 担当 | 実行方式 |
|---------|------|--------|
| 調査 | 必要な独立調査担当、または親 | ランタイムが提供する実行方式 |
| 集約・分析 | 親、または親が選んだ担当 | ランタイムが提供する実行方式 |
| 仮説 | 親、または親が選んだ担当 | ランタイムが提供する実行方式 |

---

## ステップ 0: 実行コンテキストの確認

対象、現在の status/diff、既存の入力、親から渡された保存先を確認する。記録が必要な場合だけ、親が選んだ安全な実在ディレクトリ内の未使用 path を使う。特定ランタイムのホームディレクトリ、固定メモリ配置、パス正規化を推測しない。

記録を保存する場合は、親が選んだ安全な実在ディレクトリ内の未使用 path に新規作成し、既存ファイルを上書きしない。

このワークフローは、特定ランタイムの handoff、メモリ、保存先を前提にしない。

---

## ステップ 1: 調査フェーズ

研究テーマを独立したサブ問いに分ける価値がある場合だけ、現在のランタイムが提供する read-only 委譲 primitive へ調査を渡す。分離の利益が小さい場合や primitive がない場合は、親が直接調査してよい。

### 選択ルール

- 独立した問いが複数ある場合は、実害、必要な根拠、容量に応じて並列または wave 実行する。固定の最低数・上限・モデルを完了条件にしない。
- 入力はユーザー要件、実在する対象・資料、必要な場合の一次資料に限定し、推測で補わない。

### 担当へ渡す内容

- 対象、問い、確認済み事実、受入条件、変更禁止範囲を渡す。
- 後続判断に必要な場合だけ、親が選んだ安全な実在ディレクトリ内の未使用 path へ結果を新規作成する。保存しない場合は返却内容を親が統合する。
- 実装・ファイル編集・git 状態変更をさせず、実在する根拠と不確実性だけを返す。外部資料を使う場合は参照 URL を添える。

### 調査観点

- テーマに関する既知の事実・定説・データ（一次情報の出典付きで）
- 対立する見解・論争点・未解決の問い
- 関連する先行事例・類似ケース（ローカルの資料・コードにあれば含める）
- 情報の確実性（一次ソースか二次ソースか、どこまで裏が取れているか）

### 追加調査

初回確認で正しさ、安全性、権限、仮説形成に影響する不明点が残る場合だけ、原因に対応する追加調査を行う。追加回数、担当数、保存形式だけを完了条件にしない。

---

## ステップ 2: 集約と必要な確認

### 2-1: 集約

実在する調査結果を親が読み、1本に統合する。統合時に以下を行う:

- 複数 explorer が重複して報告した事実は1つにまとめる
- 出典のある事実と、出典が弱い/推測混じりの情報を仕分ける
- explorer 間で食い違う記述があれば「対立点」として明示する（潰さない）

集約結果を保存する場合は、親が選んだ安全な実在ディレクトリ内の未使用 path に新規作成する。フォーマット:

```markdown
## 集約結果: [研究テーマ]

### 確定的な事実（出典あり）
- [事実] — 出典: [URL / ファイルパス]

### 不確実・出典が弱い情報
- [情報] — [なぜ不確実か]

### explorer 間の食い違い（該当する場合）
- [論点]: explorer-01 は X、explorer-02 は Y

### 調査で埋まらなかった空白
- [まだ分かっていないこと]
```

### 2-2: 必要な確認

集約結果を親が要件、スコープ、成功条件と照合する。研究の方向、外部・不可逆操作、権限など結果を実質的に変える判断が残る場合だけ、根拠と選択肢を示してユーザーへ確認を求める。形式や artifact の有無だけで停止しない。

判断を記録する場合も、親が選んだ安全な実在ディレクトリ内の未使用 path だけを使い、未生成の記録を後段の必須入力にしない。

---

## ステップ 3: 思考フェーズ

実在する集約結果をもとに、親または現在のランタイムの委譲 primitive が選んだ担当が、論点、パターン、因果関係、論理構造を分析する。

- 担当には研究テーマ、実在する集約結果、確認済み事実、変更禁止範囲を渡す。新規情報を推測で補わず、必要な場合だけ親が選んだ安全な実在ディレクトリ内の未使用 path に分析結果を保存する。

思考レポート要約を受け取る。

分析で追加調査が必要な論点が見つかった場合は、仮説形成への影響を親が判断する。仮説を妨げない不足は「未解決の問い」に繰り越し、判断を実質的に変える不足だけ追加調査へ戻す。

追加調査へ戻すのは、情報不足が仮説形成や安全な判断を妨げる場合だけとする。回数や担当数を固定せず、未解決の問いは根拠とともに明示する。

---

## ステップ 4: 仮説フェーズ

実在する集約結果と分析結果をもとに、親または現在のランタイムの委譲 primitive が選んだ担当が、検証可能な仮説を作る。担当を起動できない場合は親が直接行う。

- 担当には研究テーマ、実在する分析・集約結果、確認済み事実、変更禁止範囲を渡す。各仮説に根拠、検証方法、反証条件、確信度を添え、必要な場合だけ親が選んだ安全な実在ディレクトリ内の未使用 path に保存する。

仮説レポート要約を受け取る。

---

## ステップ 5: 研究レポートの統合

実際に確認した集約・分析・仮説を、必要な場合だけ **1 本で完結する研究レポート**に統合する。保存する場合は、親が選んだ安全な実在ディレクトリ内の未使用 path に新規作成する。

### 自己完結の原則（最重要）

このレポートは single source of truth。**読者が中間ファイル（synthesis / thinking-* / hypotheses-*）を一切開かなくても、この 1 本だけで事象・根拠・仮説・優先順位・残課題まで意思決定できる**ように書く。

- **要約に痩せさせない**。中間ファイルの結論だけを箇条書きで転記して終わらせない。事実・数値・根拠（コード位置 `file:line` / 出典 URL）・各仮説の「根拠 / 検証方法 / 反証条件 / 確信度」・トレードオフ・ロードマップの成功判定指標まで、判断に要る情報は省略せず転記する。長くなってよい（情報量を減らさない）。
- **Overview（要約）を最上部に置く**（下テンプレートの `## 0`）。結論・規模・根本原因・最重要の一手を先に書き、詳細は後段に積む（逆ピラミッド）。**ここだけ読めば全体が掴める**ようにする。要約を末尾や中間に埋めない。
- 視覚構造（見出し階層・表・コードブロック・引用バッジ）で、長くても読めるようにする。
- 中間ファイルは「通常は参照不要」の付録扱いとし、パスだけ末尾に載せる。

### テンプレート

実在する集約・分析・仮説の資料を読み、以下に**詳細を転記**する（見出しはテーマに応じて増やしてよい。判断に必要な情報を省略しない）:

```markdown
# [研究テーマ] 研究レポート

_作成: YYYY-MM-DD_

> 📌 このファイルは single source of truth。中間成果物を読まなくても、この 1 本で意思決定できるように書いてある。

## 0. Overview（エグゼクティブサマリ）

- 結論・規模・根本原因・最重要の一手を数行で。**ここだけ読めば全体が掴める**ように。

## 1. 問い・背景

[研究テーマ・発端]

## 2. 調査で分かったこと（集約）

[synthesis.md の「確定的な事実（出典つき）」「不確実な情報」「食い違い」「空白」を、要点だけでなく根拠ごと転記]

## 3. 思考（分析・論点）

[thinking-*.md の因果構造・パターン・トレードオフ・論理の吟味を転記]

## 4. 仮説

[hypotheses-*.md の全仮説を「根拠 / 検証方法 / 反証条件 / 確信度」つきで転記。最有力仮説・検証ロードマップ（各手の成功判定指標つき）も含める]

## 5. 未解決の問い

[各段で残った空白を統合。何を・どの手段で確かめるか]

## 付録: 出典 / 中間成果物のパス

[主要出典 URL、および exploration-* / synthesis / thinking-* / hypotheses-* のパス（通常は参照不要）]
```

### 保存先

- 呼び出し元または親が指定した安全な実在ディレクトリ内の、今回まだ使われていない path に新規作成する。
- 保存しない場合は、実際に確認した内容をチャットで返す。未生成の path や資料を報告しない。

---

## ステップ 6: 最終サマリーの提示

以下の内容をユーザーに提示してください:

```
## Research 完了サマリー

### 問い
[研究テーマ]

### 研究レポート
[保存した場合だけ、実在する path]

### 調査（要点）
- 実施範囲: [実際に確認した対象・観点]
- 主要な事実: [1〜2文]

### 思考（要点）
- 中心的な論点/パターン: [1〜2文]

### 仮説
- 実際に立てた仮説と確信度: [要約]
- 最有力仮説: [1文。なければ none]

### 検証ロードマップ（最初の一手）
- [最有力仮説を確かめる最小ステップ]

### 未解決の問い
- [残った空白があれば]

### 未確認事項・blocker
[なければ none]
```
