# Chat — 深掘り対話

このスキルは明示的な `/chat <問い>` で起動します。通常の会話へ自動適用せず、ユーザーの問いに必要な深さ・根拠・具体性を親が選びます。

## 1. 問いの読み方

- 先に結論、目的、前提、ユーザー固有の制約を把握する。
- セッションで既に示されたOS、リポジトリ、設定、予算、期限を再質問しない。
- 依頼が短い回答を求める場合はその長さを守る。深掘りを理由に長文化しない。
- 不明点が回答を実質的に変える場合だけ、一つの具体的な質問または選択肢を返す。

## 2. 裏取りの判断

次の情報は変化し得るため、利用可能な実際のWeb・検索・文書取得操作で一次資料を確認する: 現在/最新の仕様、価格、法令、ニュース、リリース、ライブラリAPI、比較候補の現行状態、ユーザーが指定したURLや資料。安定した一般知識、雑談、与えられた本文の要約は、外部調査なしで答えられます。

技術的な主張は公式ドキュメント、仕様、リリースノート、公式リポジトリなど一次資料を優先します。比較や技術選定では、候補のバージョン・サポート状況・制約を同じ基準で確認します。コードベースの意味は、親または現在のruntimeが提供する標準の探索担当・汎用 Task へ、対象・版・確認事項を明示して渡します。実行者名を完了条件にしません。

runtime固有の tool 名、製品名、存在しないAPIを共有本文で仮定しません。利用可能な操作が不明・失敗・権限不足なら、未確認の範囲と理由を明示し、推測で埋めません。外部調査をした場合だけ、回答中に実際に参照したURLと確認内容を示します。

## 3. 委譲

委譲は、問いが独立しており親の直接確認より精度または網羅性が上がる場合だけ行います。親は対象、確定事実、問い、編集禁止、返却事項と、必要な実行者用 Skill / reference の実体 path を渡し、子が必要な資料を Read します。親が直接確認する場合だけ、自分が必要な資料を Read します。担当にレポート保存、メモリ追記、コード変更、外部投稿を要求しません。ライブラリ選定を分離する場合は、実在する技術検証担当または親が担当し、役名だけを理由に子を増やしません。子はこの親用 `/chat` の進行を再起動しません。

## 4. 回答の形

問いに応じて次の構造を使います。全項目を機械的に出す必要はありません。

```markdown
## 結論
[最初に答えと前提]

## 詳細
[根拠、手順、具体例、コード、数値]

## 選択肢と注意点
[比較、トレードオフ、反証。該当する場合のみ]

## 次に役立つこと
[依頼に直接関係する落とし穴や次の操作。該当する場合のみ]

## 参照
[調査したURLやローカルの実在パス。未調査なら省略]
```

回答は一般論で打ち切らず、与えられた文脈に結び付けます。数値、コード、条件分岐は、確認できた根拠がある場合に限って具体化します。確証のない内容は推測・未確認としてラベル付けします。

## 5. 境界

`/chat` の回答だけを理由に実装、設定変更、commit、push、外部投稿を開始しません。明示された別の作業依頼があれば、その作業に対応するスキルへ移ります。回答の完了条件は、問いに必要な根拠と前提、残る不確実性を、要求された深さで返すことです。
