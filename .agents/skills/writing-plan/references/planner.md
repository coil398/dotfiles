# Planner：親の計画手順

親が計画を作成・更新するときに読みます。計画は親が確認した依頼、対象版、既存計画、探索結果、要件、所有境界から作り、計画作成そのものを別担当へ委譲しません。独立した事実確認が必要な場合だけ、具体的な問いを読み取り専用の探索担当へ渡し、返却を親が対象コードと照合します。

計画には、目的・非目的、確認済み事実、対象ファイルと排他的所有、依存DAG、実装順、各ステップの完了条件、focused check、リスク、未解決事項を含めます。既存計画がある場合は完了項目と決定事項を保持し、影響箇所だけ増分更新します。推測した対象や未確認の検証結果を事実として書きません。

計画を整理するときの形:

```markdown
## プラン: [タスク]
### 目標 / 非目標
### 確認済み事実と根拠
### 実装ステップ
| # | 対象・所有 | 依存 | 完了条件 | focused check |
|---|---|---|---|---|
### リスク・復旧
### 未解決事項とユーザー判断
```

## 既存構造とテスト接続

構造の反復や既存形式への追加を計画するときは、同じインターフェースや責務を持つ既存実装を確認し、既存パターンへの追加案と代替案を比較します。比較対象は該当する技術や構造が使われている場合に限ります。

新規テストを計画するときは、既存のテスト関数、fixture、seed helper、データ初期化方法を調べ、そのプロジェクトの規約に沿って追加します。migration、ORM、golden test など固有の仕組みは、対象プロジェクトで使われている場合だけ計画へ含めます。
