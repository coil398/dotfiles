# Writing-plan — 計画・実装・記録

**タスク**: `$ARGUMENTS`

親がユーザー対話、要件、対象、計画、スコープ、依存、所有、統合、受入、最終判断を所有します。計画作成を別担当へ委譲せず、独立した調査・実装・レビューだけを現在のruntimeの委譲機構へ渡します。

このスキルに同梱された参照文書は、読み込んだ本 `SKILL.md` の実体から同じ skill package 内の `references/` を解決します。

## Review/test の接続

レビューまたはテストが必要な場合、同じ親が shared skill package の実体にある `../reviewer/SKILL.md` または `../tester/SKILL.md` を存在確認して読み込み、その手順を実行します。別の進行担当を起動せず、親は対象版、要件、ユーザー指定、実在する計画・差分、必要な確認範囲を渡し、選定・配分・集約は shared skill に委ねます。

shared reviewer は評価者へ `code-review-guidance/SKILL.md` の実体絶対パスと対応する reference だけを渡し、reviewer の進行手順を評価者へ渡しません。shared tester は `tester/references/test-procedure.md` と結果契約の実体を実行担当へ渡します。親が自ら評価・検証する場合だけ、必要な専門手順を読みます。この workflow では観点、未知指定、担当間の分離、判定規則を再定義しません。

## 1. 計画

開始時に依頼、現在の対象版/status/diff、既存計画、関連コード、成功条件を確認します。要件を変える未決定だけをユーザーへ確認し、既に確定した事項を再質問しません。探索は親が直接行うか、独立した問いだけを読み取り専用の探索担当へ渡します。`--deepplan` が明示された場合だけ deepplan を使い、結果を親が対象コードと再照合します。

親は [references/planner.md](references/planner.md) を読み、その手順で計画を作成・更新します。

計画には以下を含めます。

- 目標、非目標、確認済み事実、受入条件
- 対象ファイル、排他的所有、変更禁止範囲、依存順
- bite-sized な実装ステップと各ステップの完了条件
- 変更された挙動に対応する focused check、レビュー、テスト
- 主要リスク、復旧方法、未解決事項

既存の計画・ユーザー資料がある場合、完了項目・決定事項・対象版を保持し、影響箇所だけ増分更新します。設計評価を存在しないコードdiffの評価へ変換しません。計画だけの依頼では、計画と残る判断を返して実装を開始しません。

## 2. 記録

後続実装が参照する、またはユーザーが保存を求めた場合に、親が計画記録を作成・更新します。保存先は既存方針または親が指定した親directoryの実在を確認したうえで、その配下の今回未使用のファイルpathに限定し、未指定のRUN_DIR、handoff、台帳、空のreportを推測・先行作成しません。通常は次の形を使います。

```markdown
# [タスク] 実装記録
_作成: YYYY-MM-DD | ステータス: 進行中_
## 目標
## 実装計画
- [ ] ステップ 1: ...
## 設計詳細
## 実装ログ
## 未確認事項
```

## 3. 実装と委譲

小さく密結合した変更は親が直接行います。独立単位を委譲するときは、目的、確認済み事実、対象版、所有範囲、制約、編集権限、完了条件、focused check、返却事項と、必要な実行者用 Skill / reference の実体 path を渡し、担当自身に必要な資料を Read させます。親が直接実行する場合だけ、必要な資料を親が Read します。担当同士の再委譲、無断の計画変更、所有範囲外の編集を前提にしません。readerには保存、記憶追記、コード変更、テスト生成を要求しません。実行者へ親用 `/writing-plan` の計画・実装・記録ループを渡して同じ工程を再起動させません。

親は各ステップ後にstatus、対象diff、実在ファイル、受入条件、実行結果を照合します。担当の自己申告や終了コードだけで受入しません。ユーザーや他担当の未コミット変更を戻さず、明示範囲外のreset、restore、checkout、stash、commit、push、外部投稿を行いません。

## 4. レビューとテスト

親は前節の shared reviewer/tester に、対象版、要件、ユーザー指定、実在する差分・計画、必要な確認範囲を渡し、返却された実在の結果を受入判断へ使います。実行結果、未確認範囲、対象版を記録します。reviewer/tester の返却が要件未達・未確認を示した場合、未完了をPASSへ変換せず、原因を特定して影響範囲だけ修正し、影響する確認だけを shared skill の手順で再確認します。同じ原因を根拠なく繰り返しません。

## 5. 完了

要求された変更、必要なレビュー、必要な検証が完了したら記録を完了に更新します。任意の改善、追加規則、全体再点検を完了条件へ加えません。完了報告には実装記録の実在 path、変更ファイル、実施した確認、未確認事項を示します。未完了、権限不足、取得不能、明示モデル不在が残る場合は `INCOMPLETE` として次の操作と理由を記録します。
