# 状態と一貫性の照合

product-planning の第8節で、企画書・モック・デザインを突き合わせ、状態の漏れと既存画面との不一致を実装前に洗い出す手順です。

## 状態の照合

企画書の「状態」の一覧を起点に、画面ごとに次の表を作ります。行は状態、列は企画書・モック・デザインです。

- 各セルには、その状態で何が表示され、何ができるかを書きます。
- 一つでも空のセルがあれば漏れです。企画書・モック・デザインのどれを正とするかを決め、残りを直します。
- 一覧にない状態がデザインやモックに現れていれば、企画書の一覧へ足します。

確かめる状態の例です。この企画に当てはまるものを選び、当てはまらないものは理由を一行残します。

- データがない、少ない、多い、文字が長い
- 読み込み中、通信エラー、サーバーのエラー、タイムアウト
- 初めて使う、久しぶりに使う、途中で離れて戻ってきた
- 契約・課金・権限・年齢などによる表示の違い
- 上限に達した、期限が切れた、対象外になった
- 端末の大きさ、表示言語、文字サイズ、ダークモード

## 一貫性の照合

第2節の内部探索で確かめた既存画面と、次の点を比べます。違う箇所は、既存に合わせるか、違えることを企画書で決めるかのどちらかにします。理由なく違うものを残しません。

- 部品（ボタン、リスト、ダイアログ、タブなど）の形と使い方
- 配色、文字の大きさ、余白、アイコン
- 文言の言い回し、用語、同じものの呼び方
- 遷移の仕方、戻り方、確認ダイアログの出し方
- 同じ操作に対する結果の出し方（完了表示、エラー表示）

## 結果の扱い

- 直した内容は、企画書・モック・デザインの全部へ反映します。どれか一つだけを直しません。
- 直した内容が企画の狙い・対象ユーザー・体験を変える場合は、企画書の段階へ戻り、反論とペルソナ評価をやり直します。
- 照合が済んだら、企画書の受入条件に、照合で決めた状態ごとの表示と既存画面に合わせた点を足します。
