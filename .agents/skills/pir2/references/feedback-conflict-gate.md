# 関連するユーザー指示との整合確認

実装や委任内容を、今回の依頼、適用される指示、すでに参照した関連資料と意味で照合する。古い資料の語句一致、固定期間、固定件数だけで矛盾や停止を判定しない。

## 確認する内容

- 変更対象と除外範囲が、最新の明示指示と一致しているか
- 依頼された機能や検証を、説明なく縮小していないか
- 過去の資料が今回にも適用され、その後の指示で上書きされていないか
- 権限、データ保護、公開契約、安全境界など維持すべき制約に反しないか

関連する経緯が不足する場合だけ、利用可能な project memory や長期記憶を必要な範囲で参照する。毎回同じ日数・件数を読み直したり、該当なしの証跡ファイルを作ったりしない。

## 矛盾を見つけた場合

根拠を依頼、実差分、関連資料に照らして再確認する。最新の明示指示による明確な変更はそのまま反映し、不要な再承認を要求しない。親が依頼の範囲内で解消できる場合は、影響する計画や委任内容だけを更新する。

正しさ、安全性、データ保護、公開仕様に関わる未決定事項、または権限外の変更が必要な場合だけ、根拠と選択肢を示してユーザーへ判断を求める。独立して完了できる作業は進め、矛盾と無関係な全工程を止めない。

判断の経緯が後続作業に必要な場合は、既存の計画または親が選んだ実在する run/artifact に相違と解消内容を記録する。記録作成そのものを完了ゲートにしない。
