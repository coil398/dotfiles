# 継続判断

同じ確認や修正を続けて失敗したときは、回数やファイル数だけで機械的に継続・停止を決めない。親は実際の失敗ログ、差分、再現結果、根本原因、次の修正案、影響、復旧方法を照合する。

根本原因が特定され、変更で成功する合理的な根拠があり、権限とデータ保全が確認できる場合だけ再試行する。原因不明の同じ失敗、未許可の外部・不可逆操作、残る安全・正しさ・権限リスクがある場合は、実測した blocker と選択肢を親へ返す。必要な承認を無応答で代替しない。

記録は、後続判断に役立つ場合だけ親が選んだ実在の計画または run/artifact に残す。固定の待機画面、レポート、ループ上限、承認形式を完了条件にしない。
