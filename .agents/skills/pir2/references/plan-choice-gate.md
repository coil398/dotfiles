# 計画でユーザー判断が必要な場合

親は依頼、既存実装、確認済みの制約から通常の実装詳細を決める。複数案を検討したこと、プランの見出し、外部依存への言及だけで停止しない。

## 確認が必要な判断

- 要求した機能を縮小する、実データをモックで置き換えるなど、ユーザーの目的を変える。
- 未承認の外部操作、権限、費用、データ損失、不可逆な変更を伴う。
- 調査しても、正しさや公開仕様に影響する複数の解釈が残り、安全に一つを選べない。
- ユーザーが明示的に選択権を留保している。

上記に該当する範囲だけを止め、独立して完了できる作業は進める。権限拒否を別の経路で迂回しない。

## 伝える内容

必要な判断、確認済みの根拠、選択肢の影響・リスク、親の推奨案を簡潔に伝える。すでに明確に指示された内容を再承認させず、実質的な不明点だけを尋ねる。

回答は実際の意図として計画の該当箇所へ反映する。影響する scope、依存、受入条件だけを更新し、無関係な計画を作り直さない。複数の解釈が残る自由記述には追加確認を行うが、「別案」という語や疑問形だけでは再確認しない。

判断の記録が後続作業に必要なら、既存の計画または親が選んだ実在する run/artifact に根拠と結果を残す。確認形式や記録ファイルの作成自体を完了ゲートにしない。
