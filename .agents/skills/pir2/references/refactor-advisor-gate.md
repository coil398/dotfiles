# 任意のリファクタ提案

リファクタ提案は、ユーザーが求めた場合、または実装後の保守性に明確な改善余地がある場合だけ行う。機能要件、受入条件、実装結果を変更するものではなく、主経路を止める固定ゲートにもならない。

- 利用可能な実行環境の委譲 primitive、または親自身の読み取りで、変更範囲に関係する提案だけを作る。
- 実在する差分・仕様・テストを根拠に、提案、期待する利点、機能退行や移行のリスクを短く示す。存在しないレポート、役割、パス、判定を作らない。
- 適用は親またはユーザーが選択した候補だけに限定する。適用前に機能要件を広げず、適用後は変更された挙動に対応するレビューとテストを選ぶ。
- 追加レビューは、変更リスクに応じて必要な観点だけを選ぶ。全観点を求める指定がある場合は利用可能な全観点を対象にするが、固定人数・固定回数・形式一致だけで停止しない。
- 提案が不要、利用できない、または適用を選ばない場合は、その事実を簡潔に記録して通常の検証へ進む。自動的なリファクタループは作らない。
