# Meta Retrospector — メタ・Dreaming 分析基準

この reference は、ユーザーが明示した `--meta` または `--dream` のときだけ、親が meta-retrospector へ渡す実行者用基準です。通常の振り返りからワークフロー変更へ自動拡張しません。

## 共通の入力境界

- 親が明示し、実在確認した registry、直近のバックアップ metadata、対象 Skill / Agent、観測結果だけを読む。
- `REGISTRY_PATH`、`BACKUP_ROOT`、`RETRO_REPORT_PATH` は渡された既存 path と専有範囲だけを使う。runtime の home や別の memory path を推測しない。
- registry の読取と更新、提案と適用、バックアップと復元、commit / push は別の責任である。入力を読めたことは書込承認を意味しない。
- 変更前の実績、対象版、復元可能性を確認できない提案は、未確認として返す。
- 複数の registry、memory、バックアップ metadata、対象本文、観測結果が渡された場合は、path・対象版・時点を照合して矛盾、重複、欠落、統合時の損失を分ける。片方を正として黙って選ばず、統合・削除・上書きは承認と専有範囲が揃うまで行わない。

## `--meta` の分析

1. 実在する未処理 flag と、その根拠になった実測を確認する。flag が無ければその事実を返す。
2. ループ終了条件、情報経路、責任境界、不要な固定 role・反復・成果物の有無を、現在の原本と実績で照合する。
3. 通常の本文追記で解決できる問題と、骨格変更が必要な問題を分ける。
4. 提案ごとに根拠、対象 path、変更種別、期待効果、リスク、具体的な rollback を返す。変更は親の承認後に、親が指定した writer が行う。
5. 直前変更の効果は、変更前 metadata と親が渡した現在の実測を同じ対象版・期間で比較し、改善、悪化、効果未確認を分ける。指標やベースラインがない場合に回数や効果を推測しない。形式上の flag や件数だけで新しい骨格変更を提案しない。

## `--dream` の分析

registry 全体を親が渡した場合だけ、重複、陳腐化、状態の不整合、統合時のデータ損失リスクを分類する。統合・archive・削除・上書きの候補を分け、和集合となる内容と失われる内容を示す。registry を自動で書き換えず、バックアップと承認が揃わない場合は提案で終了する。

## 返却契約

```text
実行モード: meta / dream
対象と根拠:
直前変更の効果: 改善 / 悪化 / 効果未確認 / 初回
提案:
承認・バックアップ・writer に必要な条件:
未確認とデータ損失リスク:
```

日本語で返し、追加 agent、未指定 path、権限変更、commit、push を行わない。改善候補がない場合は、変更なしで完了できる。
