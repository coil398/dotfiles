# Retro — パターン汎化・エージェント改善

実在する作業結果から学びと改善候補を整理する、親向けの振り返り手順です。親が対象、入力、保存、承認、統合、最終判断を持ち、必要な場合だけ現在のランタイムの読み取り担当へ分析を渡します。実行者用の通常・メタ基準は同じ package の `references/retrospector.md` と `references/meta-retrospector.md` にあります。
`--meta` または `--dream` はユーザーが明示した場合だけ有効です。改善不要なら変更なしで終了します。

引数: $ARGUMENTS

---

## ステップ 0: 入力とモード

引数はランタイムの構造化された引数・フラグ解析で解釈し、メタ、Dreaming、対象プロジェクトを分離します。構造化引数がない場合も、呼び出し元の引用を認識する parser を使い、未引用の shell word splitting や glob 展開で再解釈しません。対象を省略した場合は、ランタイムが渡す現在の対象を使います。

`DREAM_MODE` は `META_MODE` より優先します。`PROJECT_PATH`、証拠資料、既存の保存先は親が実在確認してから渡します。保存先が渡されない場合はファイルを作らず、会話へ結果を返します。

---

## ステップ 1: 振り返り範囲と担当の選択

`DREAM_MODE` / `META_MODE` の値に応じて振り返りの範囲を選ぶ:

- `DREAM_MODE=true`: registry の統合・整理を含む Dreaming モード
- `META_MODE=true`: ワークフロー骨格の改善提案を含むメタモード
- いずれも `false` または未指定: 通常の振り返り

実績の独立分析に利益がある場合だけ、現在のランタイムが提供する標準の読み取り担当を起動します。担当には、親が確認済みの対象、実在する入力、今回のモード、変更禁止範囲、返却方法、必要な実行者用 reference の実体 path を渡します。利用できなければ親が直接確認し、担当の起動を完了条件にしません。モデル名・role表をこの Skill に固定しません。

担当へは、対象、実際に存在するログ・差分・計画・検証結果、モード、目的、変更禁止範囲を渡す。実験定義や観測ログを使う場合も、今回読み込んだ skill package または親が明示した実在の path を使い、未生成の artifact を要求しない。

追加メッセージは reference の返却契約を使います。読み取り担当は report、memory、registry を保存せず、追加委譲、commit、push を行いません。

---

## ステップ 2: 結果の提示

実際に確認した情報、学び、改善候補、残るリスク、未確認範囲だけを提示します。report を保存した場合だけ実在する path を示し、未生成の成果物や未測定の値を補完しません。メタ・Dreaming で変更や統合が必要になった場合は、影響、復元方法、承認が必要な範囲を示し、親が承認済みの writer にだけ適用を渡します。
