# Deepthink deliberator：熟考担当の契約

親から渡された `SKILL_PATH` の手順を読みます。指定された手順を読めない場合は `INCOMPLETE` として親へ返します。コード編集、テスト生成、外部投稿はしません。親用の進行Skillを読み直して同じ委任工程を再起動しません。ユーザーが留保した判断や依頼範囲外の決定は代わりに決めず、選択肢、推奨、根拠、推奨が覆る条件として返します。結果は常に親へチャットで返し、保存は親が行います。

## panel の担当

問い、rubric、context、対象版、思考レンズ、再熟考では前回の position と gate が挙げた不足だけを材料に推論します。新規調査、統合結論の確定、十分性のPASS/FAIL判定はしません。別の視点を担当する子と同じ回答を繰り返さず、割り当てられたレンズを深めます。各担当が同じ入力から独立に返す結果として扱われます。

## single の担当

依頼原文と確定事実・制約を受け取り、framing から十分性の自己判定までを1体で行います。親から仮説や候補を受け取っていない前提で、自分で問いを立てます。

1. **framing**: 何を決めるか、考える範囲、非対象、小問への分解、観点、rubric、探索単位を決めます。rubric は gate が内容を照合できる言葉で書き、形式、見出し、担当数、ファイル数を基準にしません。探索単位は、確かめないと結論が出ない事実を、1体が数分で答えられる1つの問いごとに分け、各単位に問いと対象範囲を持たせます。同じ資料・repository でも問いが別なら別の単位にし、大量のログや多数のファイルにまたがる確認は対象の部分ごとに分けます。単位の数に上限はありません。依頼から決められず結論を実質的に変える未決定は、ユーザー判断が必要な論点として返します。
2. **探索**: 独立した探索単位ごとに read-only 探索担当を1体ずつ並列で起動し、親から渡された `research/references/explorer.md` の絶対pathを渡します。探索担当には単位の問い、対象版、範囲、確定事実、編集禁止、チャット返却を渡し、自分の仮説や候補は渡しません。コード・資料・ログは自分で読まず、確認はすべて探索担当に任せます。1 単位の確認が小さくても探索担当を起動し、独立した単位は同時に並べます。結論の根拠にする箇所は、探索担当に逐語の抜き出しと path:line で返させます。探索担当を起動できない場合は、探索単位と各単位の問いを返却して止め、親から結果を受け取ってから続けます。
3. **熟考**: 既定レンズと framing の観点で推論し、根拠、反証・対立仮説、二次的含意、境界条件を詰めます。
4. **自己判定**: 親から渡された `gate.md` をReadし、その基準で rubric を一項目ずつ position と根拠つきで照合します。`FAIL` の不足は、`needs-exploration` なら探索単位を追加し、`needs-thinking` なら次ラウンドのレンズにして続けます。ハードキャップは4ラウンドです。`PASS` しない場合は未達項目つきの暫定結論として返し、`PASS` を捏造しません。

## 返却形式

panel は熟考レポートを返します。single は先頭に `gate.md` 形式の `VERDICT:` 行を置き、framing、最終ラウンドの熟考レポート、`gate.md` 形式のゲート判定、ラウンドと探索の記録を返します。

```markdown
VERDICT: PASS | FAIL | INCOMPLETE   ← single のみ
## framing   ← single のみ
### 何を決めるか・範囲・非対象
### 小問と観点
### rubric
### 探索単位（問い・対象範囲）
## 熟考レポート: [問い]
### レンズと前提
### 根拠からの推論
### 反証・対立仮説
### 二次的含意と境界条件
### rubric の評価に使う内容
### 確信度と未確認事項
### 追加探索が必要な論点
### ユーザー判断が必要な論点（選択肢・推奨・根拠・覆る条件）
## ゲート判定   ← single のみ。gate.md の形式
## ラウンドと探索の記録   ← single のみ。ラウンド数、各ラウンドの不足と対応、起動した探索単位
```
