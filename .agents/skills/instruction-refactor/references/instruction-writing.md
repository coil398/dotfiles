# 指示ファイルと文書の書き方

instruction file（グローバル・プロジェクトの `AGENTS.md` / `CLAUDE.md`、`.agents/skills/**/SKILL.md`、`.cursor/agents/**`、adapter overlay）と、`DESIGN.md`・README・仕様書・設定内コメントなど現在の状態を記述する文書を書く・直すときに読む。

## 今どうあるべきかだけを書く

- 現在の規則と状態だけを書く。instruction file では、行動を変える理由も一般形で書いてよい
- 変更前の状態、変更の経緯と理由、却下した案、ユーザーとのやり取りは書かない

**書かない例**

- 「X をやめた」「X から Y に変えた」と、その理由。現在の規則（「X を使わない」「Y を使う」）だけを書く
- 事案・パターン・チケット・PR の ID（`P-015`、`MT-1234`、`#123`）。形式の例示が必要なら `MT-<番号>` のようにプレースホルダで書く
- 事案の日付や再現描写、ユーザー発言の引用
- 日付付き移行注釈（`（2026-08 移行）`、`移行済み`、`廃止後`）
- 「X は廃止。Y を使え」型のバナー（Y の手順だけ書く）
- 「旧 X からの置き換え表」「Coplay → CLI」など、現行経路を旧ツール名で説明する見出し
- 読者の行動が変わらない経緯・先例・ユーザーの反応

**書いてよい例**

- retro / incident / deepthink / handoff / CHANGELOG など、履歴が成果物である文書内の日付・経緯

**自己チェック**: その文を消しても読者が取る操作が同じなら、消す。

## Skillの書き方

- Skillは `SKILL.md` のmetadataから発見される。descriptionには、できることと実際の作業境界を簡潔に書き、主な用途を先に置く。何でも拾う発火条件や、起動を繰り返し求める文を避ける
- 選んだSkillと、今回のモードに必要なreferenceだけを読む。参照先は、読む条件と一緒に示す。編集のたびに全文書の通読を要求しない
- 1つのSkillは1つの仕事をする。大きな手順・参照資料・script・assetは `references/`・`scripts/`・`assets/` に置く
