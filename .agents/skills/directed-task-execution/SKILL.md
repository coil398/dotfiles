# 判断と実行を分担する

親が目的、仮説、原因の解釈、設計、修正方針、比較条件、実行範囲を決める。作業者は監視、情報収集、親が具体化した手順の実行を担当する。安価なモデルを使う場合も、この責任分担を変えない。

## 親が渡す指示

- 対象と所有範囲、参照する既存成果物、変更してよいもの。
- 実行する手順、固定する条件、成功・失敗・停止の判定根拠。
- 監視の間隔と終了条件、異常時の連絡先、結果の保存先。
- 作業者が判断せず親へ戻す条件。未知のエラーや次の手順がない場合は、観測を保存して親へ返す。

作業者が安全に実行できる粒度まで指示する。原因究明や再実験の設計を、曖昧な「適当に直して」で作業者へ移さない。

## 既存セッションを継続する

既存セッションへの継続指示は、そのセッションに送信する。新しい操作セッションやCLIの起動へ置き換えない。操作用セッションの継続と、そこで次のジョブを実行することを区別する。

- ユーザーが指定した対象と作業だけを指示する。並行する別タスクの目的・修正方針・待機条件を混ぜない。
- 対象、実送信、受理、実行開始を確認する。準備済みや送信待ちを実施済みと報告しない。
- 許可済みの可逆な実験・継続指示を、自分で追加したレビュー待ちで止めない。
- 操作制限の対象を本人の指示どおりに扱う。GUI操作の禁止を、CLIや端末の文字入力・編集の禁止へ勝手に拡大しない。

送信経路の故障や操作審査の拒否は、対象セッションの終了と区別して返す。拒否された操作を別経路で迂回しない。最新の明示認可が得られた場合は、その認可対象を理由に記載して正式に再審査する。

## 作業者が返す情報

実プロセス、最新成果物、終了記録などの観測事実を、時刻と参照先つきで返す。指示の送信、受付、起動、成果物生成、検証完了を区別する。仮説は事実と分け、原因の確定、比較結果の解釈、方針変更は親へ戻す。

新たな再起動、条件変更、修正、再実験を独自に決めない。事前に親が指定した条件分岐は、その範囲で実行できる。経過時間や親の無応答を許可として扱わない。

## 監視と報告

ユーザーへの定例報告と作業者の監視は別の間隔で設定する。報告時刻を待たず異常を親へ通知し、親が根拠を確認して具体的な次手順を返す。監視担当が終了・中断した場合は、継続監視中と報告しない。全対象の終端を確認したら監視を終える。

親は監視の反復を作業者へ任せ、判断が必要なイベントと成果物の確認に集中する。実行方式は対象環境で既に利用可能なものを使い、この分担自体を権限やスコープの拡大と解釈しない。
