## 成功基準（rubric）: W0+W1（6-3 決定論的完了検証ほか）の最終深レビュー

### この熟考のゴール
本セッションで実装した変更 ―― W0（citation 衛生＋epic の sanitized_cwd 登録）と W1（`deterministic-completion-check.md` 共通プロトコル・pir2 ステップ 6-3・pir2codex 共通化・`verify-deterministic-check.sh`・implementer.md の NO_OP マーカー）―― を多エージェントで深くレビューし、**コミット/採用してよいか、残すべき懸念は何か**を客観判断材料として出す。行レビュー（ドッグフーディング＋sonnet×3＋fable×2 で実施済み・全 PASS）では出ない **設計適合・システミック影響・採用可否** の論点に照準する。

### スコープ / 制約
- **in scope**: 実装済み変更ファイル一式の設計妥当性、観測された失敗（事象X=resume 時 implementer 捏造→reviewer 全FAIL→19分迷走）への対処適合、完成形設計（`docs/deepthink/20260703-190750-Fable5.md` の移行パス W1→W5）における W1 としての整合、全 pir2/pir2codex 通常 run への挙動影響、experimental（epic executions 0）に対する投資の妥当性、コミット/採用の推奨。
- **out of scope**: これ以上の実装変更（本熟考は「レビューと推奨」まで）。epic フローの全面再設計。W2 以降の実装。
- **前提**: 行レベルの正確性は既に多重レビューで PASS 済み。本レビューは「行が正しいか」でなく「**正しいものを作ったか・出荷してよいか**」を問う。deliberator には実コード（reference の bash 全文等）を context に逐語で渡す。

### 充足基準（gate はこれを一項目ずつ客観照合する）
| # | 基準 | 充足の判定方法（何があれば充足か） |
|---|------|-----------------------------------|
| 1 | **oracle の健全性**を系統的に判定 | git-diff 集合照合が「捏造検出」の oracle として健全かに明確な判断。残存限界（git 検証不能・submodule・入れ子フェンス・実在 gitignore への虚偽申告）が**正しく境界づけられ受容可能か**を、偽陽性/偽陰性の方向（fail-open/fail-closed）つきで評価している |
| 2 | **設計適合（root cause 対処）**を判定 | 6-3 が事象X（resume 時の捏造→reviewer 全FAIL→迷走）の連鎖を**実際に断ち切るか**を機序で判定。「症状（捏造の下流）を止めるが根本（resume 時の認識論的真空）は別対処が要る」等の適合度を明示。かつ完成形設計の移行パスにおける W1 としての整合（W2+ の土台になるか）を評価 |
| 3 | **全通常 run への挙動影響**を具体列挙 | 捏造していない大多数の pir2/pir2codex run に対し、必須ゲート追加が課すコスト（偽陽性リスク・オーケストレーターの bash 実行負担・レイテンシ・複雑性/保守）を具体で列挙し、コストが**釣り合っているか**を判定 |
| 4 | **完成度・残ギャップ**を網羅 | 未実装/見送り（決定1 の 7-4/8-2 未配線・pir2async 未対応・`.codex` overlay・W2 以降）を列挙し、各々が「真のギャップ」か「妥当なスコープ境界」かを判定 |
| 5 | **過剰/過小設計の判定**（experimental 前提） | epic executions 0 の試験機能に対し、投じた堅牢化（5 実装ラウンド・verify スクリプト・6 フィクスチャ）が過剰でないかを、最有力の反論「0 回機能にやり過ぎ」を steelman したうえで判定 |
| 6 | **採用/コミット推奨**を明示 | 明確な推奨（そのままコミット / 修正してコミット / 保留 / ロールバック）を根拠つきで提示。コミットで**ユーザーが受容する残存リスク**を列挙 |
| 7 | **プロセス自己言及の考察** | 本開発で私の修正指示（FIX-5・FIX-F）自体が regression を作り後段レビューで捕捉された事実が、「人間主導 fix ループ」の信頼性、および 6-3 機構自身の信頼性（自分の開発バグを機械検証で捕まえた）について何を示すかを考察 |
