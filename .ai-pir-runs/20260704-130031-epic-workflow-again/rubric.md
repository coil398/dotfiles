## 成功基準（rubric）: epic ワークフローの実行 readiness と次の一手

### この熟考のゴール
W1（決定論的完了検証 6-3 の共通基盤）をコミットした現時点で、epic ワークフロー（`/epic` SKILL.md ＋ epic-planner、Epic executions 0 の試験実装）を **今どうすべきか** を決める ―― 具体的には「今の epic を実際に1回回せる状態か」「次に作るべき最小の W2 は何か、それとも W2 なしで dry-run できるか」「L1 ネスト pir2 ランナー設計を実行に移すのは安全か」を評価し、**明確な次の一手を1つ**出す。

### スコープ / 制約
- **in scope**: コミット済み `/epic` SKILL.md ＋ `epic-planner.md` の現状の実行可能性、完成形設計（`docs/deepthink/20260703-190750-Fable5.md`）の移行パス W1→G1→W2→G2→W5 における現在位置、G1 dry-run（1-unit epic）を今回せるか、L1 が pir2 全体を自律オーケストレーションできるかという未実証の核、初回実 run の安全な最小構成。
- **out of scope**: W2 の実装（本熟考は評価と次アクションの推奨まで）。epic の全面再設計（deepthink 2 で実施済み）。改善点の再列挙（deepthink 1 で実施済み）。
- **前提**: 直近の W0+W1 深レビュー（`docs/deepthink/20260704-002417-review-w0w1-6-3.md`）が「6-3 は phantom-claim floor・L0 自己捏造には可監査性のみ・再帰的信頼は W5 hook で錨」等を確定済み。本セッションで実エージェントのフリーズ・parse 失敗・ゾンビ成功を複数観測している。deliberator には epic SKILL.md/epic-planner の実記述を context に逐語で渡す。

### 充足基準（gate はこれを一項目ずつ客観照合する）
| # | 基準 | 充足の判定方法 |
|---|------|----------------|
| 1 | **現状の実行可能性を評価** | コミット済み `/epic` SKILL.md が今のまま end-to-end で回るか、回すのに欠けている具体ギャップ（未定義の手順・依存する未実装機構・L1 起動プロンプトの過不足）が列挙されている |
| 2 | **G1 dry-run の可否を判定** | 「W2 を先に作る必要があるか」対「W2 なしで最小 G1 dry-run（1-unit・additive-only）を今回せるか」に根拠つきの判断。dry-run で観測すべき未知（L1 自律性・Agent 同期/非同期・テレメトリ return・6-3 の epic 内発火）が特定されている |
| 3 | **L1 ランナー設計の実行時健全性** | 「general-purpose L1 が pir2 全13ステップを自律オーケストレーションできるか」という未実証の核を評価。L1 が失敗した時の実際の挙動と A-lite フォールバックの妥当性、失敗検知手段（テレメトリ契約不履行）が示されている |
| 4 | **初回実 run の安全性** | プラットフォーム所見（ネスト Agent 深さ・#44783 並列ハング・再帰的信頼・本セッションで観測したフリーズ/parse 失敗/ゾンビ成功）を踏まえ、初回 run が安全か判定。安全な最小構成（直列・1〜2 unit・additive-only・fan-out OFF）が具体で示されている |
| 5 | **次の一手の推奨を1つ確定** | 「G1 dry-run を今やる / 最小 W2 を先に作る / 保留」から1つを根拠つきで確定（玉虫色禁止）。推奨した一手の**具体的な最初のタスク題材・構成・観測項目**が示されている |
| 6 | **W1 と過去 deepthink との整合** | 推奨が W1（6-3）と移行パス上で整合し、過去3本の deepthink 結論と矛盾しない（矛盾するなら更新点を明示）。epic を experimental.md の Active 実験として観測する既存方針との接続 |
