# コードベース探索の委譲

親 Astra が探索の範囲、結果統合、実装判断を所有する。この文書は独立した探索を委譲するときだけ使い、すべての作業での事前読込や子の起動を要求しない。専門手順は `.agents/skills/research/references/explorer.md` と `tech-validator.md` を原本とする。

## 経路の選択

- 既知の単一ファイル、狭い検索、`git status` / `git log` / `git diff` は親が直接確認できる。
- 複数ファイルの構造把握、独立した既存パターン探索、外部仕様の裏取りは、分離によって待ち時間または証拠の独立性が改善する場合だけ標準子へ委譲する。
- 独立した問いは並列化できる。実行時の空き枠と設定上限の低い方を守り、依存する問いは先行結果を受け取ってから開始する。
- 子からの追加委譲は親が明示した場合だけ許可する。実装、レビュー、テスト、ユーザー対話、最終受入は親に戻す。

## 子へ渡す内容

対象版、具体的な問い、確認済み事実、調査範囲、編集禁止、期待する根拠と未確認事項を渡す。専門手順が必要なら、親が実在を確認した原本の絶対 path を渡し、子自身に読ませる。対象 repo や HOME から path を推測させず、親用の進行 Skill を再起動させない。

調査範囲はユーザーが指定したファイル・機能・キーワードと、答えに必要な依存へ限定する。広域探索が必要な場合は、その理由と終了条件を問いに含める。調査担当は結果を親へ返し、report・記憶・リポジトリを変更しない。

## 統合

親は各レポートの対象ファイルと根拠を照合し、ファイル単位の和集合から実装スコープを判断する。担当内のラベル番号だけで結果を束ねない。不明点が完了条件に影響するときだけ具体的な追加問いを出し、同じ失敗や確認済み範囲を反復しない。
