# Worker Delegation

このSkillは、親Astraが判断・設計・分割・統合・最終受入を所有し、必要な具体作業を Codex の native collaboration で子へ渡すための契約です。小さな変更や全体文脈と分離できない密結合の変更は、Astraが直接実装します。起動方法（`spawn_agent`、`fork_turns="none"`、`followup_task`、並列数の上限）は Codex Native Runtime Supplement に従います。

## 担当とmodel

子の model と推論量は `.codex/config.base.toml` の `[agents]`（`default_subagent_model`、`default_subagent_reasoning_effort`）の既定に任せ、委譲のたびに繰り返し指定しません。原因推論、状態・所有権、競合、性能、厳しい整合性などが中心の難しい独立作業は、親が起動時に `model="gpt-6-sol"` と `reasoning_effort="high"`、または難度に応じて `"max"` を明示して初手から選べます。

入力不足、仕様未決定、権限、環境、外部サービス、CLIの失敗はmodel不足の証拠ではありません。親はその原因を解消するかユーザー判断へ戻し、model変更は十分な入力を渡したうえで能力不足を差分・再現・確認結果から実測した場合だけ判断します。子や親の手順に自動fallback、無条件の再試行、model/effortの自動変更を置きません。

作業単位ごとに担当、所有ファイル、制約、受入条件を明示し、独立した書き込み単位だけを並列化します。同じファイルや共有契約を複数担当へ同時に割り当てません。

## 委譲内容

担当ごとに次を短く渡します。

- 目的と既に確認した事実
- 所有するファイルまたは領域（他担当との重複なし）
- 維持する制約、変更してよいインターフェース
- 終了条件と実行すべき焦点を絞った確認
- 変更してはいけない範囲
- 返却する変更ファイル、挙動の変更、実行結果、未確認事項、blocker

探索・調査だけを渡す場合は、編集禁止を明示し、共有 `research/references/explorer.md` の実体絶対 path を渡して担当自身に読ませます。独立した問いだけを並列化し、結果は対象ファイルと論点で統合します。

委譲担当は指定された範囲だけを編集し、判断の変更やスコープ拡張を親へ戻します。別agent、reviewer、testerを勝手に起動せず、commit、push、既存変更を破棄する操作もしません。権限や安全境界をモデル変更の理由で弱めません。

## 受入

子の返却は自己申告として扱います。Astraは実際の `git status`、対象差分、変更ファイル、要求された確認コマンドの出力から各受入条件を判定します。reviewer/testerを使う場合は担当とは別系統で実行し、その判定を担当の返却へ混ぜません。起動していないreviewer/testerの結果を作りません。

全受入条件を実測して満たした場合だけAstraが完了とし、未実行の確認、未対応事項、外部状態のblockerを明記します。委譲の効果を比べる場合は、既存のtask reportに task種別、実モデル・effort、担当変更の理由、所要時間、検証、手戻り、取得できた利用量を残します。利用量が取得できなければ未計測とし、ゼロや推測の費用削減を記録しません。
