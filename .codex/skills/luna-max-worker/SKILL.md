# Luna Max Worker

Solをオーケストレーター、GPT-5.6 Luna Maxを実行担当として扱う。判断・設計・タスク分解・完了要件・最終判定はSolが所有する。

## 責任境界

- Sol: ユーザーとの対話、調査、判断、計画、作業範囲、完了要件、実行後の要件適合判定を担当する。
- Luna Max: 具体化済みの作業と指定された検証だけを実行する。
- `reviewer`: correctness、security、regression、保守性などの品質を評価する。本スキルのPASSは品質保証を意味しない。

Lunaへ曖昧な設計判断、スコープ拡張、優先順位決定、完了判定を委ねない。必要な品質条件がある場合は、Solが完了要件へ明記する。

## 実行手順

### 1. 委譲可能か判定する

次をすべて満たす場合だけLunaへ委譲する。

- 作業が具体的で、対象範囲を特定できる。
- Solが主要な設計判断を済ませている。
- 完了要件を成果物またはコマンドで検証できる。
- Lunaが不明点を独断で補わなくても実行できる。

満たさない場合はLunaを起動せず、Solが不足情報を解決する。

### 2. タスク契約を作る

一時ディレクトリを`mktemp -d`で作り、次の2ファイルを置く。リポジトリ内へ一時ファイルを残さない。

`task.md`:

```markdown
# 目的
<実現すること>

# 作業範囲
<所有ファイル、変更可能な領域、実行してよいコマンド>

# 実装指示
<Solが決定した具体的な手順・制約>

# 禁止事項
<変更禁止領域、スコープ拡張禁止など>
```

`requirements.md`:

```markdown
- R1: <成果物またはコマンドで真偽を判定できる完了要件>
- R2: <完了要件>
```

抽象的な「良い感じ」「高品質」だけを完了要件にしない。

### 3. Luna Maxを実行する

同梱ランナーをforegroundで起動する。実行が継続中ならセッションをポーリングし、60秒以内にユーザーへ進捗を伝える。

```bash
<skill-dir>/scripts/run-luna-max.sh \
  --cwd <対象リポジトリの絶対パス> \
  --task-file <task.md> \
  --requirements-file <requirements.md> \
  --output-file <luna-result.md>
```

ランナーは`gpt-5.6-luna`と`model_reasoning_effort="max"`を固定し、`workspace-write`で`codex exec`を実行する。別modelやeffortへフォールバックしない。

Lunaが質問、判断不足、権限不足、CLIエラーを報告した場合は成功扱いにしない。勝手に別手段へ迂回せず、Solへ制御を戻す。

### 4. Solが要件適合を判定する

Lunaの自己申告を合否根拠にしない。Sol自身が次を実測する。

1. `git status -sb`と対象差分で、実際の成果物を確認する。
2. `requirements.md`の各要件に対応するファイル、出力、または検証コマンドを確認する。
3. 要件ごとに「満たす / 満たさない」を判定する。

品質観点を追加でレビューしない。品質レビューが必要なら、本スキル完了後に`reviewer`を別途使う。

### 5. 結果を報告する

```text
評価: PASS / FAIL
要件:
- R1: 満たす / 満たさない — <実測根拠>
- R2: 満たす / 満たさない — <実測根拠>
Luna実行: <変更内容と実行した検証の短い要約>
```

全要件を満たす場合だけPASSにする。FAILでも自動修正やLunaへの差し戻しは行わない。

## 安全規則

- Lunaへ本スキルの再呼び出しや別エージェントの起動をさせない。
- ユーザーの既存変更を戻させない。
- `git reset --hard`、`git checkout --`、広範な削除、無断commit/pushをさせない。
- Lunaの作業範囲をファイルまたはモジュール単位で明示する。
- CLIが`max`を拒否したら停止する。`xhigh`等へ変更しない。
- 実コンテンツ衝突、破壊的操作、新しい権限が必要な場合はSolへ制御を戻す。
