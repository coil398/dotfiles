# 観点別レビューの分担と統合

Astra が実差分と受入条件から必要な観点を選ぶ。ユーザーが明示した観点と実害防止に必要な観点を保持し、固定人数や宣言形式を品質条件にしない。

## 観点

- correctness: 正確性、性能、挙動の回帰。
- consistency: 構造や同一ロジックの適用漏れ。
- quality: 局所的な保守性、テスト品質、スコープ逸脱。
- security: 認証・認可、入力・外部境界、秘密情報。
- architecture: 責務・レイヤー・依存境界。

独立観点が複数なら各観点を別担当へ並列に渡す。アクティブ設定の `max_concurrent_threads_per_session` と実行時空き枠の低い方を守り、空き枠不足は wave を分けるか利用可能な既存 thread を `followup_task` で再利用する。単一観点なら単独でよい。担当には対象差分、実在する計画と実装結果、受入条件、固有の report パス、読み取り専用の制約を渡す。

## 受入

Astra が指摘を仕様・差分・テストで照合する。採用した重大指摘は解消し、誤検知と判断したものは根拠を残す。必要な観点が未確認・判定不能なら PASS にしない。

起動が複数ターンに分かれた、宣言テンプレートがない、という理由だけで得られたレビューを破棄しない。不足した観点だけ追加し、修正後は影響した観点だけ再確認する。

refactor-advisor は不具合レビューとは別の任意改善。必要時は同じ references directory の refactor-advisor-gate.md に従う。
