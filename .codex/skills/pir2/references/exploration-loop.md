# 追加探索と計画の増分更新

Astra が計画に残る未確認事項を具体的な topic と成功条件へ分ける。確認済み事実を再調査せず、判断に必要な不足だけを扱う。

1. EXPLORATION_ROUND を 0 から数える。
2. 小さく密結合した確認は親が行い、独立 topic は各担当へ並列に渡す。アクティブ設定の `max_concurrent_threads_per_session` と実行時空き枠の低い方を守り、完了済みを空き枠と推測しない。利用可能な既存 thread は `followup_task` で再利用する。
3. 対象、禁止範囲、既存証拠、確認したい問いを渡す。report が必要なら実行前に固有パスを確定する。
4. 返った事実を Astra が統合し、既存 plan の根拠・scope・依存・要件だけを増分更新する。計画全体を破棄しない。
5. 明示された deepplan の場合は同じ RUN_DIR と既存計画を引き継ぎ、その skill の追加探索手順へ戻る。

追加探索は最大5回を見直し点とする。到達時に不明点が残る場合、正しさ・安全性に必要なものを未確認のまま実装へ流さない。原因を説明し、証拠に基づく別の調査か必要なユーザー判断へ進む。非致命的な改善だけを backlog に分離し、未確認事項を最終結果へ明示する。

同じ失敗を根拠なく再試行しない。既存設計からの逸脱や権限外の操作は、適用指示に従い実装前に確認する。
