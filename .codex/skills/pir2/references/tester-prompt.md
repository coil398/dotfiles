# tester 実行プロンプト

Astra が実差分、計画、利用側とプロジェクトの検証規約から TEST_SCOPE を定義する。実行するコマンドと、その確認で防ぐ具体的な実害を担当へ渡す。

## 検証範囲

- 変更した挙動の再現・回帰テスト、生成物や公開契約の利用側を必要に応じて含める。
- 文書・設定でも実行指示、権限、生成、公開挙動に影響すれば、その挙動を検証する。影響しない文書変更は構文・リンク・内容照合などで足りる。
- フルスイートは影響範囲から必要な場合、または適用されるプロジェクト規約で必須の場合に実行する。ファイル数や固定フラグだけで追加しない。
- 完了済みの同じ確認は証拠と対象 revision を照合して再利用できる。独立検証が必要な安全性・正しさの確認を worker の自己申告で代替しない。

## 担当への入力

独立した動作検証に分離価値がある場合は tester role を起動する。小規模な確認は Astra が直接行える。担当には以下を渡す。

- PROJECT_ROOT、対象差分、必要な受入条件、実在する plan/report のパス。
- TEST_SCOPE のコマンド、実行ディレクトリ、必要な環境、期待する結果。
- 変更禁止範囲、外部サービス・本番データ・不可逆操作への権限境界。
- レポートを保存する場合は実行前に確定した固有パス。

必要な追加確認が見つかったら、理由と影響を Astra に戻す。親が依頼範囲内の安全な確認と判断できる場合は実行し、権限・費用・外部データなど新たな承認が必要な場合だけユーザーへ確認する。テストデータ以外の既存データをクリーンアップしない。

## 結果と再実行

実行したコマンド、終了コード、確認結果、未実行・判定不能の理由を返す。必要な確認が未完了なら PASS にしない。FAIL は再現した原因を修正経路へ戻し、変更後の影響に応じて必要な確認だけを再実行する。関係のない成功済み検証を取り消さない。
