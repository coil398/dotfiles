# 関連するユーザー指示との整合確認

実装や委任内容を、今回の依頼・適用される指示・既に参照した関連feedbackと照合する。古いfeedbackの語句一致や件数だけでは矛盾と判定しない。

## 確認する内容

- 変更対象や除外範囲が、最新の明示指示と一致するか。
- 依頼された機能や検証を、説明なく縮小していないか。
- 過去のfeedbackが今回にも適用されるか。その後の指示で上書きされていないか。
- 権限・データ保護・公開契約など、維持すべき制約に反しないか。

関連する経緯が不足する場合だけproject memoryやai-ltmを必要範囲で参照する。毎回固定日数・固定件数を読み直したり、該当なしの証跡ファイルを作ったりする必要はない。

矛盾を見つけたら根拠を照合し、親が依頼の範囲内でplanや委任内容を修正する。最新指示による明確な変更はそのまま反映し、再承認を要求しない。正しさ・安全性に関わる未決定事項や、権限外の変更が必要な場合に限りユーザーへ判断を求める。

判断の経緯が後続作業に必要なら、既存planまたは `{RUN_DIR}/feedback-conflict.md` に実際の相違と解消内容を記録する。記録作成だけを完了ゲートにしない。
